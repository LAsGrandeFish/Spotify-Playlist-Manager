Project: Spotify Playlist Manager

Project Type:
Full-stack playlist review and cleanup web application

Project Summary:
Designed and built a keyboard-centric Spotify playlist management application that helps users review large playlists, decide which tracks to keep or remove, add tracks to other playlists, and confirm batch changes in one workflow. The app combines a multi-stage review experience with persistent review sessions, resumable state, Spotify playback integration, and a Prisma-backed data layer to make large-library cleanup faster and more deliberate.

Tech Stack:
- Next.js 16 (App Router)
- React 19
- TypeScript
- Tailwind CSS
- Prisma ORM
- PostgreSQL
- Spotify Web API
- Spotify Web Playback SDK
- react-range
- ESLint
- Prettier

Core Features:
- Keyboard-driven review workflow for playlist cleanup
- Playlist viewer with metadata table, playlist hero, and incremental track loading
- Review mode for keep, remove, undo, add-to-playlist, and new-playlist actions
- Batch confirm flow that applies Spotify mutations in chunks
- Persistent review sessions that allow in-progress work to be resumed
- Playback support inside review mode using Spotify playback integration
- Summary screen with review results, confirm status, retry support, and confirm-attempt audit history
- Post-confirm reconciliation to compare expected changes against refreshed Spotify data

Implementation Details:
- Structured the product around three primary states: viewer mode, review mode, and summary/confirm mode
- Implemented a session-backed review model in Prisma to store review sessions, reviewed tracks, actions, add targets, and confirm attempts
- Built a resilient confirm pipeline that supports partial failure handling, retrying only failed chunks, and post-confirm reconciliation
- Added Spotify OAuth-based authentication and token refresh handling to reduce stale-session failures during longer review sessions
- Integrated Spotify playback into the review interface and paired it with custom playback controls and a progress slider
- Used typed request/response flows across client and server routes to keep review state, persistence, and Spotify writes coordinated

Why It Matters:
This project demonstrates full-stack product development, third-party API integration, persistent workflow design, failure-aware batch mutation handling, and the ability to build a polished user-facing tool around a real usability problem.
